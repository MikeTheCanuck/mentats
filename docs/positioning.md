# Positioning — the actual problem this solves

This is the point of view Mentats exists to argue for. Keep it intact when writing the README or LinkedIn posts — sharpen the prose if needed, don't blur the argument.

## The problem

Not everyone will be able to afford frontier models for all their work. As token subsidies come off and open-weight models close the gap from "good enough" to "very good," it becomes increasingly viable — and increasingly necessary — to route as much work as possible to local models, reserving frontier models for supervising the grind rather than doing it.

Concretely, right now: paying $100-200/month for *more* (and still not unlimited) frontier tokens isn't the answer. What's actually wanted is the ability to let ideas run without constantly supervising, surveilling, or second-guessing them mid-flight. Hitting an escalation wall every few minutes is tedious. Getting stuck and not making demo-worthy progress — forced to wait hours or days for a usage window to reset — kills momentum outright, which is worse than tedious: it's the difference between finishing something and abandoning it.

The goal is harnessing the full power of Apple Silicon sitting idle on a desk to blaze through projects, without tying one hand behind your back to a 5-hour retry window on a $20/month subscription, and without having to remember to babysit every step.

Betting that individuals will need to get as efficient about personal token spend as organizations are already being forced to get about enterprise token spend. This project is a bet on that trajectory, built now, ahead of most people needing it.

## What this means for how the project is presented

- README and LinkedIn posts lead with this argument, not with "here's a CCR+Maestro config." The tool is evidence for the thesis, not the thesis itself.
- Not selling "save money" as the headline — selling "stop losing momentum to a usage window you don't control."
- The audience this should resonate with: people running real, sustained agentic work solo, hitting the same wall, who haven't yet framed it as a token-economics problem they can solve themselves the way enterprises solve it with FinOps.
